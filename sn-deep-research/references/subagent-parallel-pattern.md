# 并行子代理取证模式

## 适用场景

当 `plan.json` 中有多个无依赖维度（`depends_on` 为空）需同时取证时，使用 `delegate_task` 并行派发以缩短总研究时间。

## 工作流

```
父代理: 确认维度清单 → 分批派发(每批≤3个) → 等待全部返回
                                     ↓
                   子代理A → 广度发现 → 搜索不? → 写子报告 → 退出
                   子代理B → 广度发现 → 搜索不? → 写子报告 → 退出
                   子代理C → 广度发现 → 搜索不? → 写子报告 → 退出
                                     ↓
父代理: 收集全部子报告 → 统一重写 plan.json status → 进入综合阶段
```

## 关键规则

### 1. 超时降级

- 子代理超时（600s）不重试第 3 次
- 父代理判断超时原因：如果超时伴随 web_search 返回空（在子代理的 tool_trace 中可观察到），由父代理直接用训练知识撰写该维度子报告
- 降级后写入的子报告必须在顶部标注"搜索不可用"

### 2. 避免 JSON 竞态

**问题**：多个子代理同时调用 patch 修改 `plan.json` 会导致 JSON 格式损坏（如缺少逗号、花括号不匹配）。

**解决方案**：
- 子代理只负责写入 `sub_reports/{dimension_id}.md`
- 父代理在全部子代理返回后，统一从零重写 `plan.json` 的所有 `status` 字段
- 重写时使用 `write_file`（全量覆盖）而非 `patch`（增量替换），确保 JSON 完整性

### 3. 搜索检测

每个子代理在 `web_search` 首次执行广度发现时，必须按 `sn-dimension-research` 的搜索可用性探测规则检测。检测到的不可用状态不会跨子代理共享——每个子代理独立检测。

### 4. 语言一致性

子代理默认使用英文总结。如果用户要求中文输出，必须在 `delegate_task` 的 `context` 参数中显式指定"respond in Chinese"或"用中文写作"。

### 5. 产物检查

父代理收齐全部子代理返回后，检查：
- 每个子报告是否非空
- 每个子报告是否标注了搜索状态（可用/不可用）
- 如果搜索不可用，子报告是否在"不确定性与空白"节列出了因无法搜索而缺失的信息

## 曾遇到的坑

| 问题 | 表现 | 修复 |
|------|------|------|
| JSON 竞态 | plan.json 中某维度后的 JSON 对象的 context diff 显示重复或缺失内容 | 父代理统一重写 plan.json，不做增量 patch |
| 子代理反复重试搜索 | 超时 600s，tool_trace 显示 15+ 次 web_search 均返回空 | 在子代理中植入搜索不可用检测，3 次空结果即降级 |
| 子代理未标注限制 | 子报告写了丰富内容但未提及搜索不可用 | 父代理收齐后统一补标注 |
