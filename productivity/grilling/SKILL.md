# Grilling Skill — 设计树访谈

源自 Matt Pocock 的 `grilling` 技能。核心思想：**按"轮次"遍历决策树**，每轮问当前 frontier 上所有可问的问题，给出推荐答案，用户回答后推进到下一轮。

## 触发场景

- 用户说"帮我理清这个需求"、"讨论一下这个设计"、"帮我规划"
- 用户说"你觉得这个方案怎么样"、"我想听听你的分析"
- 用户表达了一个模糊的想法或计划，需要结构化的梳理
- 任何需要深度讨论和决策树遍历的场景

## 核心概念

**设计树 (Design Tree)**：每个决策分支成更细的决策。根节点是用户的原始需求，每层分支是必须回答的问题。

**Frontier (前沿)**：当前轮次中，所有前置条件已满足、可以问的问题的集合。

**轮次 (Round)**：每轮问整个 frontier 的问题，用户回答后，已解决的决策往前推进，暴露出新的 frontier。

## 流程

### 1. 建立设计树

从用户的原始需求出发，识别出需要决策的关键问题。不要一次性问所有问题 — 按**层级**组织：

- 第一层：最核心的决策（"我们要解决什么问题？"）
- 第二层：核心决策的细化（"用什么技术？"、"谁用？"）
- 第三层：更细的实现细节

### 2. 按轮次推进

每轮做三件事：

1. **计算当前 frontier** — 所有前置依赖已满足、可以问的问题
2. **问整个 frontier** — 每个问题带推荐答案，编号排列
3. **等待用户回答** — 用户回答后进入下一轮

### 3. 问题格式

每个问题按以下格式组织：

```
❓ **Q1** - **<问题标题>**: <问题描述，可能多段，包含选项>

➡️ <你的推荐答案>
```

### 4. 关键规则

- **事实由你查，不要让用户查** — 需要查文件和环境的，用 `delegate_task` 或 `terminal` 查，不要问用户
- **不阻塞** — 如果某个问题需要查事实，但查的过程不影响其他问题，先问其他问题
- **用户只做决策** — 你的工作是提供选项和推荐，用户的工作是挑一个
- **每轮问整个 frontier** — 不要挤牙膏，一次性把当前可问的都问完

### 5. 完成条件

当 frontier 为空时结束 — 设计树的每个分支都已访问，没有遗留的隐性假设。

**不要自动执行** — 结束前确认用户是否已达共识（"我们的理解一致了吗？"）。

## 与 Hermes 计划技能的配合

- `grilling` 做需求访谈 → 然后可以调用 `plan` 写实施计划
- `grilling` 做设计讨论 → 然后可以调用 `plan-implement-review` 执行
- 如果需要更深的领域建模，先用 `grilling` 梳理需求，再导入 `domain-modeling` 技能

## 常见陷阱

- ❌ **一次问太多问题** — 每轮只问当前 frontier 可回答的问题，不要问需要前置条件的问题
- ❌ **不给出推荐答案** — 每问必带推荐，没有推荐 = 你没有深入思考
- ❌ **让用户替你去查** — 需要查文件、代码、文档的，用 delegate_task 查
- ❌ **一轮只问一个问题** — 浪费回合，应该把整个 frontier 问完
- ❌ **用户没确认就自动执行** — 结束前必须确认共识
