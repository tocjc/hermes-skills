## 模糊量词→具体数值 对照表

| 原文 | 常见场景 | 建议替换 |
|------|---------|---------|
| 海量数据 | 存储需求 | ≥100TB 首期，支持年增 ≥30TB |
| 高并发 | 读写/检索 | ≥200 QPS |
| 多通道 | 信号采集/处理 | ≥64 通道 |
| 大体积文件 | ATFX/音频文件 | 单文件 ≥2GB |
| 长时间 | 连续采集/处理 | ≥4 小时 |
| 快速响应 | 查询/检索 | ≤2s |
| 良好的 | 性能/效果 | 删除或量化 |
| 较强的 | 鲁棒性/抗干扰 | 指定 SNR 范围 |
| 行业标准 | 对标/兼容 | 指定具体软件名称及版本 |

## 验收条款审查清单

逐条检查每条验收指标：

- [ ] 基准工具/软件是否指定了品牌和型号？
- [ ] 测试数据集是否指定了来源、规模、类别分布？
- [ ] 测试硬件环境是否指定了 CPU/GPU/内存/存储？
- [ ] 通过/失败阈值是否数值化？
- [ ] 测试方法是否明确（第三方/现场演示/盲测）？
- [ ] 测试样本量是否足够（统计学意义）？
- [ ] 重复测试次数是否指定？
- [ ] 验收不通过的补救措施和整改周期是否指定？

## 典型错误案例

### 案例 1：验收标准无基准
```
✗ "所有声学指标计算结果与行业标准专业分析软件结果偏差≤5%"
```
**问题**：没说对标什么软件，5% 对 SPL 和响度含义完全不同。

### 案例 2：选择性条款
```
✗ "搭建分布式高并发业务数据库/搭建高性能单机业务数据库"
```
**问题**：投标人可选单机，后期扩容时招标方无法要求升级。

### 案例 3：弱措辞
```
✗ "支持多通道 ATFX 文件批量解析"
```
**问题**："支持"非强制，投标人可不实现。

### 案例 4：重复编号
```
✗ "（5）安全验收：..."
   "（5）功能验收：..."
```
**问题**：两个（5），引用时产生歧义。

## 文档结构优化建议

标准招标技术需求书的推荐章节顺序：

```
一、项目总则
  1.0 术语与定义（新增）

  1.3 通用约束要求
  1.4 投标人必备资质（新增）

  2.1~2.N 各模块详细功能需求
三、数据格式与技术标准
  3.1 数据格式
  3.2 系统配置格式
  3.3 引用的标准规范
四、交付物要求
五、性能与验收标准
六、投标人技术方案要求
七、质量保证与技术支持
八、项目实施计划
```
