# Loop-Me Skill — 工作流循环设计

源自 Matt Pocock 的 `loop-me` 技能。发现用户生活中的**循环模式**，设计**工作流规范**来自动化或简化它们。

## 触发场景

- 用户说"我每天都要做 XXX，太烦了"
- 用户说"帮我设计一个自动化流程"
- 需要理解用户的工作流来设计工具或自动化
- 用户说"把我这个流程做成 skill"

## 核心概念

**Loop (循环)** — 用户生活中重复出现的模式：职业、每周、每天、每个重复活动。

**Workflow (工作流)** — 一个循环的规范，让它可执行。存在 `workflows/*.md` 中。

**Checkpoint (检查点)** — 需要人参与的节点，人来做验证或决策。

**Push right (向右推)** — 把检查点尽可能往后推，让人在最后一刻一次性确认。

**Brief (简报)** — 检查点呈现的内容：紧凑、决策就绪的摘要。

## 词汇

| 术语 | 定义 |
|------|------|
| **Trigger** | 每次运行的触发条件：事件（新邮件、新 issue）或定时（每天早上） |
| **Checkpoint** | 需要人参与的节点，验证或决策 |
| **Push right** | 尽可能晚地让人参与，之前的事情全部自动化 |
| **Brief** | 检查点呈现的紧凑决策摘要 |

## 流程

### 1. 了解用户的世界

如果 `NOTES.md` 为空或很薄，先访谈用户：
- 使用什么工具？
- 处理什么渠道？
- 他们自己的术语是什么？

### 2. 用 Loop 视角

把用户的生活看作循环中套循环。发现值得自动化的循环。

**已经重复 3 次以上的手动操作 = 值得自动化。**

### 3. 设计工作流

用 `grilling` 逐轮访谈，直到工作流规范写完。每个工作流一个文件 `workflows/<name>.md`。

### 4. 完成标准

当实现者 agent 可以不问任何问题就构建出这个工作流时，才算完成。

## 工作区结构

```
workflows/
├── morning-triage.md    ← 每天早上处理邮件和通知
├── weekly-report.md     ← 每周生成报告
└── deployment.md        ← 每次部署的流程
NOTES.md                 ← 用户的工具、渠道、术语
```

## 与 Hermes 技能配合

- `loop-me` 发现循环 → 用 `grilling` 讨论细节
- 设计好的工作流可以做成 `cronjob`
- 复杂的工作流可以拆成多个 `cronjob` 配合

## 常见陷阱

- ❌ **不先了解用户世界** — 不知道用户用什么工具，设计的工作流用不上
- ❌ **不 push right** — 让人过早参与，浪费效率
- ❌ **工作流太大** — 一个工作流只做一个循环
- ❌ **不记术语** — 用户的术语要记在 NOTES.md 中
