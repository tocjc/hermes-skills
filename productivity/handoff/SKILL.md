# Handoff Skill — 会话交接

源自 Matt Pocock 的 `handoff` 技能。当当前会话需要结束，但工作尚未完成时，生成一份交接文档，让另一个 agent 在新会话中无缝继续。

## 触发场景

- 会话太长需要重启
- 需要把工作交给另一个 agent 继续
- 需要记录当前进度供明天继续
- 用户说"这活你干不完了，交接一下"
- 模型上下文窗口快满了，需要压缩

## 流程

### 1. 理解上下文

回顾当前会话中的关键信息：
- 任务目标是什么
- 已经做了什么（已完成的工作）
- 当前状态（正在做什么，卡在哪里）
- 待完成的工作

### 2. 生成交接文档

写一份交接文档，包含以下内容：

```
# 交接文档: <任务标题>

## 会话时间
<日期和时间>

## 任务目标
<一句话说明这个任务在做什么>

## 已完成的
- [x] 事项1
- [x] 事项2

## 当前状态
<当前正在做什么，到什么阶段了>

## 待完成
- [ ] 事项1
- [ ] 事项2

## 关键技术决策
<已做出的决策，供新 agent 了解>

## 已知问题和陷阱
<遇到的坑，需要避免的>

## 建议加载的技能
- <技能名1> — 为什么
- <技能名2> — 为什么

## 参考文件
<已创建的文件路径，新 agent 需要读的>

## 附件
<其他需要保留的信息>
```

### 3. 保存

将交接文档写到用户指定的位置（如 `~/.hermes/handoffs/` 或项目目录下）。

### 4. 注意

- **不要重复**已经记录在其他 artifact（spec、plan、ADR、commit、diff）中的内容 — 引用路径即可
- **脱敏**任何敏感信息（API key、密码、PII）
- 如果用户指定了下一轮的目标，tailor 交接文档的内容

## 与其他技能配合

- `handoff` 生成交接文档 → 新 session 的 agent 加载后读取
- 也可以配合 `session_search` 查找历史上下文
- 交接文档中的"建议加载的技能"帮助新 agent 快速进入状态

## 常见陷阱

- ❌ **重复已有内容** — 已经写在 spec/plan 里的东西，引用路径，不要重写
- ❌ **不脱敏** — 交接文档可能被传给另一个模型，必须脱敏
- ❌ **太啰嗦** — 交接文档应该紧凑，用列表和短句
- ❌ **不标记关键决策** — 新 agent 不知道之前为什么这样做，可能走回头路
