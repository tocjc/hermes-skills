# Teach Skill — 多会话教学系统

源自 Matt Pocock 的 `teach` 技能。在多个 session 中教授用户新技能或概念。使用教学工作区跟踪状态。

## 触发场景

- 用户说"教我 XXX"、"帮我学习 XXX"
- 需要多 session 逐步教授一个技能
- 用户说"我想系统学习 XXX"

## 教学哲学

真正深度学习需要三样东西：
- **Knowledge** — 从高质量、高可信度资源获取知识
- **Skills** — 通过高度相关的交互式课程获得技能
- **Wisdom** — 来自与其他学习者和实践者的互动

### 流畅度 vs 存储强度

| 类型 | 定义 | 教学方法 |
|------|------|---------|
| **流畅度强度** | 当下的记忆检索 | 容易产生虚假的掌握感 |
| **存储强度** | 长期的知识保留 | 真正的目标 |

用**理想的难度**来设计课程：
- 检索练习（从记忆中回忆）
- 间隔（随时间分布练习）
- 交错（混合相关主题练习）

## 教学工作区

当前目录作为教学工作区，包含以下文件：

```
MISSION.md                    ← 学习动机和目标
RESOURCES.md                  ← 学习资源列表
NOTES.md                      ← 用户偏好笔记
reference/*.html              ← 参考文档（可打印的速查表）
learning-records/*.md         ← 学习记录（类似 ADR）
lessons/*.html                ← 课程（主要的教学产出）
assets/*                      ← 跨课程共享的组件
```

### MISSION.md

```
# Mission: <学习目标>

## 为什么学
<用户为什么想学这个>

## 目标
<具体的学习目标>

## 衡量标准
<怎么知道学成了>
```

### 课程 (Lessons)

每个课程是一个自包含的 HTML 文件，保存在 `lessons/0001-<主题>.html`。

课程特点：
- **美观** — 清晰可读的排版，用户会回来复习
- **短小** — 快速完成，不超工作记忆
- **单一胜利** — 一个课程一个可衡量的进步
- **有引用** — 链接到高质量外部资源
- **有反馈** — 交互式练习，即时反馈

### 参考文档 (Reference)

`reference/` 中的文档是课程的压缩精华，设计为快速查阅。课程可以引用它们。

### 学习记录 (Learning Records)

`learning-records/0001-<主题>.md` 记录非显而易见的课程和关键见解。类似 ADR。

## 流程

### 1. 确定任务

先问用户为什么想学这个。如果 `MISSION.md` 为空，先访谈用户。

### 2. 填充资源

找到高质量资源，记在 `RESOURCES.md` 中。

### 3. 确定最近发展区

读了学习记录后，确定用户下一步应该学什么：既不太简单也不太难。

### 4. 设计课程

**先教知识，再练技能。** 课程需要的知识只有够完成技能练习的量。

### 5. 交互式练习

基于反馈循环：用户做练习，立即得到反馈。

## 资产 (Assets)

`assets/` 中的组件是跨课程共享的：
- 样式表（第一个组件，所有课程链接它）
- 测验组件
- 模拟器/交互式工具
- 图表辅助

重用是默认方式，不是例外。写课程前先看 `assets/`。

## 常见陷阱

- ❌ **仅依赖参数知识** — 先用 `RESOURCES.md` 找高质量资源
- ❌ **课程太长** — 一个课程要短，快速完成
- ❌ **不测最近发展区** — 太简单或太难都学不进去
- ❌ **不建 assets** — 可复用的组件要提取出来
- ❌ **不记录学习记录** — 关键见解要记下来供后续参考
